## 2 獨立重新查詢(官方 `/fapi/v1/klines`)

- 端點:`GET https://fapi.binance.com/fapi/v1/klines`(公開、無金鑰),經 `urllib` 直接呼叫,不經 ccxt。我自己的稽核共記錄 399 次請求(klines 390、exchangeInfo 1、現貨 klines 8),**全部 HTTP 200**。
- 只用公開 GET。原始 JSON 存在 `raw_api/`(292 個檔案、1.9 MB,只是證據,不是正式資料)。
- 固定日期樣本:每檔每週期 6 個窗口(W1 2020-09-20、W2 2022-05-08、W3 2024-03-10、W4 2025-06-01、W5 2026-10-20 各 7 天;W6 為最新已收盤棒)。W1~W3 早於 D2 資料起點,只比 D3。
- 分頁交界:本機資料每滿一個原抓取分頁大小(D3 為 1500、D2 為 1000),取交界前 5 根與後 4 根,**重新向官方要同一段**(新的獨立請求,不沿用原本的分頁),逐根比對。
- 兩個本機快取用的是不同程式路徑(D2 經 ccxt,D3 直接 fapi),所以同一段官方資料會分別比對兩次。

**彙總:** 固定窗口 66 組 / 6,688 筆、分頁交界 332 組 / 3,320 筆,**全部一致**。

### 2.1 比對欄位(逐欄,不是只比總數)

| 欄位 | 做法 |
|---|---|
| 開盤時間 | 用來配對每一根;API 有而本機沒有、本機有而 API 沒有,都分開計數(`missing_in_local`、`extra_in_local`,全部為 0) |
| 收盤時間 | **本機快取沒有儲存收盤時間**(只存 `[開盤, O, H, L, C, V]`)。我驗證官方 `closeTime == 開盤 + 週期 − 1 ms`,全部成立(0 不一致) |
| Open、High、Low、Close、Volume | API 字串轉 float 後與本機值**完全相等**比對(本機值也是由字串轉 float 而來),0 不一致 |

### 2.2 比對對象的限制

- 「最新」窗口(W6)的最後幾根在本機快取抓取時間(2026-11-05 15:20/15:36 UTC)之後才收盤,所以沒有拿來比;它們的筆數記在 CSV 的 `api_beyond_local_end` 欄,未計入。
- 這是**抽樣**,不是全歷史重新下載。
- BTC 的 1H 有 3 根成交量為 0(2019-09-08 18:00、2019-09-09 00:00、2019-09-09 01:00)。後兩根我對官方核實過確實是 0(成交筆數也是 0);第一根沒有單獨向官方核實。
