# D4 前向紙上交易 A/B 對照

> 狀態:**程式已完成、尚未開始觀察**。沒有建立正式實驗、沒有常駐程序、沒有排程。需要使用者確認後才啟動(見「啟動方式」)。
> 全部是模擬(SIMULATED),與 `trading-bot/` 完全隔離。觀察結果只用來看,不會自動調整實盤。

## 1 固定的研究方案

| | 內容 |
|---|---|
| A | 目前全部 23 組策略與原有配置(權重 Σ = 16) |
| B | 排除 `TRX/USDT 1h tsmom`、`XRP/USDT 1h vortex`,其餘 21 組的配置、風險參數、資金分配公式不變 |
| B 的 Σ權重 | **沿用 A 的 16**(與 D3 相同):其餘 21 組分到的金額不因移除而增加。若要改成重新分配(Σ = 14),必須另開新實驗版本 |
| 起始資金 / 成本 | 310 USD;吃單 0.05%;進場滑價 0.03%、市價出場 0.01%、停損 0.042%;風險 4.03%/筆;槓桿上限 3;`sumw_override` 16(與 D2 校準、D3 相同) |
| 開始日期 | 建立實驗時固定(UTC 整點、必須在建立之後)。開始前的 K 棒只用來暖機(需要 ≥ 400 根已收盤棒),**不計入績效**;開始時所有組合空手 |

`docs/d4_snapshot_preview.json` 是用真實 23 組設定與幣安 exchangeInfo 產生的**預覽**(開始日期 2026-11-09 只是示範,正式日期由使用者決定)。它不是正式紀錄,也沒有建立任何實驗。

### 固定與雜湊
建立實驗時寫入實驗資料夾(之後設為唯讀,同一資料夾不能再次建立):
- `config_snapshot.json`:A/B 完整組合、風險與成本參數、各策略的出場參數、交易對最小下單量/步長、起始時間與資金、資料來源規則。
- `MANIFEST.json` + `MANIFEST.sha256`:快照的 SHA-256;策略檔(`sim.py`、`integration/extra_strats*.py`)、D2 模擬器(`d2_sim.py`)與 D4 程式的 SHA-256;git HEAD;Python 版本。
- **每次 tick 都先驗證雜湊;任何一個不符就拒絕執行**(不抓資料、不寫帳本)。要改任何條件,只能建立新的實驗版本(新資料夾),不能覆蓋舊的。
- 建立正式實驗時,若上述檔案有未提交的修改會被拒絕(實驗必須對應到一個固定的程式版本)。

## 2 運作方式

```
d4_init.py   建立固定實驗(一次)                      → experiments/<id>/config_snapshot.json, MANIFEST.*
d4_tick.py   單次 tick,跑完就結束(不常駐)           → 抓新收盤棒 → 驗證雜湊 → 重播 A、B → 只附加新紀錄
d4_report.py 唯讀報告(從 ledger/ 與 bars/ 讀)        → 精簡 A/B 觀察報告(--save 另存帶時間戳的新檔)
```

- **行情**:只用幣安 USDT-M 永續合約**公開**端點(`/fapi/v1/klines`、`/fapi/v1/fundingRate`、exchangeInfo)。沒有金鑰、沒有私有或寫入端點。K 棒只收『開盤時間 + 週期 ≤ 現在 − 5 秒』的已收盤棒;儲存時再檢查一次,每根記錄抓取時間。A、B 共用同一份行情檔,所以同一時間看到的行情完全相同。
- **計算**:直接呼叫 D2 已校準的 `d2_sim.run`(只追加『記錄』欄位,不改任何計算;D2/D3 結果逐筆驗證不變)。訊號用每根棒結尾的最近 400 根已收盤棒計算並快取(append-only);視窗有缺棒就不產生訊號。
- **處理範圍**:`T1 = min(最後一根已收盤 1H − 1 小時, 所有幣 1H 從開始起連續不缺的最後一根)`,所以落後現在至少約 2 小時(等資金費率公布)。缺棒時處理停在缺口之前並記錄,**不補造資料**;缺的棒之後補齊會從缺口續算。
- **重啟安全(不重複記帳)**:每次 tick 從固定開始時間『確定性重播』到 T1,再用**事件 id**(`情境|類型|組合|時間`)和帳本比對,只附加新的事件。中途當機(檔案寫到一半)時,殘缺的最後一行會被隔離到 `ledger/corrupt_lines.jsonl`,下次 tick 補寫缺的事件。已有 id 的事件**永遠不覆蓋**;若重算結果與原紀錄不同,只會寫進 `ledger/divergences.jsonl`。
- **單一執行**:`tick.lock`(O_EXCL);超過 30 分鐘的舊鎖視為前次異常中斷,接管並記錄。
- **原始決策保存**:每筆事件記錄決策時間、決策那根的開盤時間、`recorded_utc`、`tick_id`。K 棒不被覆蓋:交易所之後若回傳不同數值,只記錄為 `bar_mismatches`。

### 帳本內容(`ledger/`)
- `events.jsonl`:`ENTRY`、`EXIT`、`FUNDING`、`REJECT`(A、B 各自)。進出場都有:`label: SIMULATED`、`expected_px`(預期成交價:進場為訊號棒收盤、停損為觸發價)、`sim_fill`(模擬成交)、`market_open`/`candle_high`/`candle_low`(實際行情)、`slip_vs_market_open_pct`、`slip_vs_expected_pct`、`fill_within_candle_range`、手續費、持倉量、損益。**模擬成交不會被當成真實成交。**
- `marks_A.jsonl`、`marks_B.jsonl`:每小時權益、錢包、暴露(名目)、持倉數(用來算回撤、最差單日、同時持倉)。
- `ticks.jsonl`:每次 tick 的摘要(新資料筆數、缺口、錯誤、鎖接管、K 棒不一致)。`status.json` 只是衍生狀態(每次覆寫),帳本才是紀錄。

## 3 與實盤的隔離(有測試檢查)
- 不讀、不用任何交易 API Key;只有一個**沒有金鑰**的公開行情連線。
- 不呼叫任何下單/撤單/轉帳/槓桿/設定 API(原始碼掃描測試:沒有 `create_order`、`cancel_order`、`set_leverage`、`fapiPrivate`、`apiKey` 等)。
- 不讀寫 `trading-bot/`:唯一讀取的設定是**已移除金鑰**的備份副本 `config.portfolio.json.REDACTED.json` 的組合清單;不覆寫任何實盤狀態檔/日誌;不修改、不停止、不重啟機器人。
- 實驗資料寫在 `paper_trading/experiments/`(已加入 `.gitignore`,不進 git)。
- 不會自動加入開機啟動或排程;沒有任何常駐迴圈(測試掃描:無 `while True`、無 `sleep`、無排程呼叫)。

## 4 啟動方式(**等你確認後才執行**)

1. 先確認 D4 程式已 commit(實驗會綁定程式版本)。
2. 建立固定實驗(選一個未來的 UTC 整點當開始日期):
```bash
python paper_trading/d4_init.py --id d4-v1 --start "2026-11-09 00:00"
```
3. 取得新資料並記帳(可以手動重複執行;每次跑完即結束):
```bash
python paper_trading/d4_tick.py --dir paper_trading/experiments/d4-v1
```
4. 看報告:
```bash
python paper_trading/d4_report.py --dir paper_trading/experiments/d4-v1 --save
```
tick 建議每 1–4 小時手動或由你自己設定排程執行一次(執行頻率不影響結果,只影響多久更新一次;隔很久再跑也會補算)。**我不會自動建立排程。** 預覽(不建立任何東西):`python paper_trading/d4_init.py --preview --id d4-v1 --start "2026-11-09 00:00"`。

## 6 限制(報告第 4 節也會列出)
- **成交是模擬**:進場 = 訊號棒後下一根 1H 開盤 ×(1+0.03%);真實成交可能因流動性、延遲、拒單、部分成交而不同。模擬成交偶爾略超出當根高低點(開盤±滑價),會照實標記並統計 `fills_outside_candle_range`。
- **不模擬**:交易所拒單、斷線漏輪(假設機器人一直在線,收盤後約 13.8 秒處理)、連敗斷路器、手動操作、帳戶保證金模式差異。
- **模擬器中斷**:程式沒跑的期間不會「漏掉」行情(下次 tick 依已存的已收盤棒補算),但這代表模擬的是『一直在線的機器人』,不是你電腦實際的在線狀況。
- **資料缺漏**:缺棒時處理停在缺口前並記錄;若交易所永久缺那根棒,處理會一直停在那裡,需要你決定(例如另開新實驗版本),不會自動補造。缺口後的訊號需要重新累積 400 根連續棒。
- **資金費率**:處理範圍落後 ≥ 2 小時才算入;使用交易所公布的歷史費率。
- **樣本與解讀**:前向期間短、樣本少;A/B 的差異可能只是雜訊(D3 已顯示 B 歷史上回撤與成本較低,但沒有一致的報酬優勢,也沒有真正獨立的 OOS)。
- 程式碼若有任何修改,既有實驗的雜湊就不符,會被拒絕續跑;需要建立新的實驗版本。
- 雜湊是對工作目錄中的檔案內容計算。觀察期間請不要對 `sim.py`、`integration/`、`validation/d2_portfolio/d2_sim.py`、`paper_trading/` 做 `git checkout`/`reset`/換分支(換行字元被改寫也會讓雜湊不符;不符時 tick 只會拒絕,不會壞資料)。
