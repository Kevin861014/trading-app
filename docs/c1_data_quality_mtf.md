# C1:多週期市場分析與資料品質檢查

範圍只有 C1(不含 C2、C3)。不改策略公式、回測、OOS、交易成本;不改 `trading-bot/`;沒有新增付費 API;`/api/mtf` 只讀既有行情(`fetch_data`,有快取)。

## 1. 現有資料處理邏輯盤點(最小必要修改的依據)
| 項目 | 原本 | C1 的處理 |
|---|---|---|
| 時框 | 1D / 4H / 1H;`tf_to_data_interval` 對不認得的時框**悄悄當成日線** | 週線只存在於 `/api/mtf`(用週線自己的資料);`tf_to_data_interval('1w')` 維持原樣,既有分析/回測的時框對照一個字都沒改 |
| 加密資料 | ccxt(幣安)原生 1h/4h/1d,已排除未收盤 | 加 `1w`(原生週線);未收盤排除沿用,並記錄「有排除」 |
| 股票資料 | yfinance 1d/1h,`_is_forming` 排除未收盤;日線時間戳 = 交易所當地日期 00:00 UTC | 加 `1wk`(週線時間戳 = 該週週一當地日期);`_is_forming` 補週線規則 |
| 4H | 加密原生;股票由 1H 依 UTC 整點合成(台股 0 根、美股對不上時段),前端標「不支援」 | 多週期同樣對台股/美股/貴金屬標示「不支援 4H」,**不合成、不替代**;加密無 ccxt 時的合成 4H 會做完整性報告 |
| 快取 | `fetch_data` 以 symbol+start+interval 為 key,TTL 3600 秒,呼叫端看不出是不是快取 | 只多記錄「怎麼來的」(`fetch_meta`:是否快取、幾秒前取得、來源、是否排除未收盤、合成報告);回傳的資料不變 |
| 訊號 | 資料再舊也會把最後一根的進出場顯示成「買進訊號！」 | 資料過期/異常時顯示「⚠ 資料過期，不顯示最新訊號」(卡片、標的分析、彈窗、導覽列、`/api/signal`);策略與回測的計算完全不變 |
| 指標 | `sim.ema`、`sim.atr`、`calc_adx`(ADX、+DI、-DI)、`market_character` | 多週期直接沿用這些函式,沒有新指標 |

## 2. 資料品質狀態(`data_quality.py`,純函式、不連網)
| 狀態 | 顯示 | 阻擋(不可當最新) | 判斷 |
|---|---|---|---|
| `ok` | 資料正常 | 否 | 以下都沒發生;休市中也是正常(附註「週末休市」「休市」) |
| `forming` | K 棒尚未收盤 | 否 | 傳進來的資料最後有未收盤的 K 棒;**已排除**,指標以上一根已收盤為準 |
| `insufficient` | 資料不足 | 是 | 已收盤 K 棒 < 60 根(60–219 根可算 EMA20/50/ADX/ATR,但沒有 EMA200,另外標註) |
| `stale` | 資料過期 | 是 | 最新已收盤 K 棒比「應有的」舊(見 §3) |
| `incomplete_resample` | 合成時間週期不完整 | 是 | 由 1H 合成 4H 時有「中間」區間缺細 K 棒被捨棄(最後一個未走完的區間是正常的) |
| `bad_timestamps` | 時間戳異常或重複 | 是 | 重複、倒退、未來、不在週期格線上、日/週線不是整日、加密近 100 根內缺 K 棒 |
| `fetch_failed` | 資料取得失敗 | 是 | 沒有資料或下載例外(附原因);品質檢查本身出錯也歸這裡,不會假裝正常 |
同時有多個問題時,以 `fetch_failed > bad_timestamps > incomplete_resample > insufficient > stale > forming > ok` 為主,其他列在 `alsoFound`。另有「資料來源不支援此週期」(`supported:false`):那不是品質問題,而且絕不用別的週期代替。

## 3. 休市與新鮮度
- **加密**:24/7。已收盤的最新 K 棒開盤時間 = 現在 − 2 分鐘寬限後的目前區間 − 1 根;落後 ≥1 根即過期。週線以週一 00:00 UTC 為格線。
- **台股/美股**:
  1. 週末一定休市;美股國定假日用 NYSE 規則計算(元旦遇週六不補休、MLK、總統日、耶穌受難日(復活節算法)、陣亡將士、Juneteenth(2022 起)、獨立紀念日與勞動節、感恩節、聖誕節,週六提前週五、週日順延週一)。
  2. 收盤後再等 30 分鐘(資料商更新)才要求當天的日線;盤中/盤前只要求上一個交易日。
  3. **台股的農曆/臨時假日算不出來,所以不硬編假日表**:只有當個股的最新日期比預期舊時,才去看大盤基準(台股 `^TWII`、美股 `SPY`)的日線當證據——大盤在那幾天也沒有 K 棒 → 休市,資料正常;大盤有開盤但個股沒有 → 過期;查不到基準 → 為安全視為過期並說明「無法確認是不是休市」。基準走既有 `fetch_data`(有快取),正常情況完全不會查。
  4. 盤中 1H:最後已收盤的 1H K 棒落後超過 2 小時 → 過期。
  5. 週線:該週最後一個交易日收盤後才算收盤(保守以週五收盤計)。
- 時區:週/日線的 K 棒時間是**交易所當地日期**;日內同時顯示當地時間與 UTC(台北 UTC+8、美東)。

## 4. 多週期技術狀態(`GET /api/mtf?symbol=&tfs=1w,1d,4h,1h`)
- 週期:週線 1w、日線 1d、4H、1H。加密四個都有(幣安原生);台股/美股/貴金屬:1w、1d、1h,**4H 標「不支援」並說明原因**。
- 每個週期各自 `fetch_data`、各自品質檢查;指標只用已收盤 K 棒:EMA20/50/200(位置與排列)、ADX、+DI/−DI、ATR 與 ATR%(沿用既有函式)。「技術偏向」只是描述:偏多 = 收盤>EMA50 且 EMA20>EMA50 且 +DI>−DI,偏空相反,其餘中性/分歧。
- 過期的週期:仍顯示歷史狀態但變淡、標明「資料過期，僅為歷史狀態」,**不列入「是否一致」的彙整**;資料不足/取得失敗/時間戳異常/合成不完整 → 不顯示指標。
- 全程標示:「只是已收盤 K 棒上技術指標目前的位置的描述,不是價格預測,也不是買賣建議」。

## 5. Research Core
`/api/mtf` 帶 `job` 時會記錄**真實發生的工作**:`data`(每個週期一筆 `i/n`、`tf`、`cached`、`ageSec`、`bars`、`ms`;需要查證休市時另有一筆基準日線事件)、`indicators`(每個週期的品質檢查 + 指標)、`summary`(彙整);`signal/backtest/validation` 明確 `skip`。市場環境頁用精簡進度列顯示(階段改名為「品質檢查＋指標」「多週期彙整」),**已快取的資料顯示「使用快取(N 分鐘前取得)」,不假裝下載**。沒有新增球體、沒有額外下載;分析/排名/深度分析的 `data` 完成事件也加了 `cached`。有/無 job 的 `/api/mtf` 回應完全相同、下載次數相同(測試)。

## 6. Research Core 兩項補強(同次交付)
- **取消分兩段**:按下取消 →「正在取消…(等待後端確認停止)」(按鈕「取消中…」,狀態 `cancelling`,不再當成進行中的工作)→ 後端真的停下並回 499 才顯示「已取消」。連線保持到後端確認;20 秒內沒確認才中斷連線並標「未收到後端確認」;若按取消時分析剛好已完成,照實顯示結果並註明。後端 `/api/job_events` 的狀態為 `running → cancelling → cancelled`。
- **事件超過保存上限**:只丟最舊的 `progress` 事件(`i/n` 是絕對計數,最新一筆即代表目前進度);`start/done/skip/error` 永遠保留,回報 `dropped` 數;完成事件帶最終絕對計數。因此各階段狀態與最終結果不會錯亂,分析結果也不受影響(測試以極小上限跑真實排名驗證)。

## 8. 已知限制 / 發現
- 既有 `calc_adx` 的 ADX 是「最後 14 個 DX 的平均」,不是教科書的 Wilder 平滑;獨立重算(pandas)的 EMA、+DI/−DI、ATR 完全吻合,但 **ADX 差約 2~11 點**(例:2330.TW 週線 16.1 對 27.4)。C1 沿用既有函式、沒有改,所以趨勢/盤整的分類門檻(25/20)沿用它的數字。是否改成標準 Wilder ADX 會牽動卡片上的市場性格徽章,留待你決定。
- 台股臨時假日靠大盤基準證據判斷;若基準也取不到,會保守標為過期。
- 貴金屬/期貨(`GC=F` 等)用美股日曆近似,不是 CME 的交易日曆。
- 週線在股票上保守地以週五收盤計,遇假日縮短的週,最後一根週線會晚一點才被視為已收盤。
- 沒有在真實 iPhone 上測試(只有模擬 iPhone 尺寸/UA/觸控)。
